# Analysis

Scripts that produce every number, table and figure in the paper from the Dataverse deposit
([doi:10.7910/DVN/4AOXKT](https://doi.org/10.7910/DVN/4AOXKT)), which is expected in `../release/`, and from ETH
prices regenerated by the pipeline (`npm run prices` in the repository root writes `../data/raw/prices/`).

Setup: `uv venv .venv && uv pip install --python .venv/bin/python -r requirements.lock`

- Full run: `./run_all.sh` (about 6 minutes). It regenerates everything from an empty `output/` and `data/`.
- Paper only, from the tracked inputs in `paper/inputs/`: `.venv/bin/python 10_render_paper.py && .venv/bin/python
  11_build_latex.py`.

| script | produces |
|---|---|
| `00_verify_release.py` | SHA-256 check of the deposit against its manifest; checks that the regenerated prices exist |
| `01_data_audit.py` | data audit and block-by-block verification of the blob schedule (`audit_fork_rules.csv`) |
| `02_build_panels.py` | day panel, rollup-day panel, zero-filled estimation panel (`data/`) |
| `03_descriptives.py` | Table 1, Figure 1 |
| `04_headline_pectra.py` | Table 2 (Pectra supply shock), placebo and wild bootstrap inference, Figure 2 |
| `05_spec_curve.py` | specification curves (Figure 3, Appendix Figure 7), per-rollup estimates (Figure 4) |
| `06_mempool_mechanism.py` | mempool-to-inclusion delay by market state (Table 3, Figure 5) |
| `07_exploratory_intraday.py` | intraday execution-base-fee analysis (exploratory) |
| `08_welfare.py` | transfers and deadweight loss (Tables 4 and 5) |
| `09_passthrough_posthoc.py` | post hoc pass-through analysis (Figure 6) |
| `10_render_paper.py` | refreshes `paper/inputs/` from `output/` when present; renders `paper/draft.md` |
| `11_build_latex.py` | `paper/arxiv/main.tex`, `main.pdf`, `paper/arxiv_submission.tar.gz` |

`est.py` holds the event-design estimator and the wild score bootstrap; `common.py` holds paths, the fork table
and the pricing-regime split.

Every number in the paper is filled from `paper/inputs/numbers/*.json` or `paper/inputs/tables/*.csv`; none is
typed by hand. `notes/PRESPEC.md` is the specification fixed before estimation, and `notes/DECISIONS.md` records
every judgement call.

Reproducibility: DuckDB aggregates in parallel, so floating-point sums can differ in the 13th significant digit
between runs. Every number in the paper is rounded well above that level.
